# ASK Forge v5.0.1 Release Notes

**Release date:** 2026-05-07  
**Release type:** Patch

## Summary

ASK Forge v5.0.1 is a governance-hardening patch after the v5.0.0 release cut. It keeps the v5 ASK Forge direction intact while tightening the runtime mechanics needed for governed autonomous software development: first-push validation, concurrent event sequencing, integration worktree isolation, durable plan ingestion, slice-scoped commits, and aligned package metadata.

This release should be treated as the stable v5.0.x adoption point for teams evaluating ASK Forge as an execution governance runtime.

## What Changed Since v5.0.0

- Expanded the README’s v5.0.0 narrative so developers can see why ASK Forge is more than renamed ASK 4.x.
- Submitted the ASK Core governance gap closure plan into ASK for governed execution.
- Fixed pre-push governance so first pushes without an upstream still scan all outgoing commits.
- Made runtime sequence allocation concurrency-safe with an exclusive sequence lock.
- Changed integration runtime validation to use real detached git worktrees instead of copied directories.
- Made plan ingestion durable by recording staged batch states for pending, completed, and failed ingestion attempts.
- Added a slice-close dirty-index guard so ASK refuses to auto-commit pre-staged work it cannot prove belongs to the active slice.
- Aligned root and `ask-core` package metadata onto the same v5 line.
- Added the missing v5.0.0 release note for the ASK Forge major release.

## Why This Patch Matters

v5.0.0 introduced ASK Forge as governed autonomous software development. v5.0.1 makes that operating model safer to rely on in day-to-day development.

The most important shift is commit and slice discipline:

- ASK slices are expected to close independently.
- Each slice should produce its own `ASK-Slice` commit after checks pass.
- Pre-push governance validates the outgoing history, including branches being pushed for the first time.
- `ask slice close` now fails before task completion if unrelated staged work is already present.

That supports the development flow ASK Forge is moving toward: plan ingestion, governed slices, runtime validation, small auditable commits, and push-time lineage enforcement.

## Compatibility

- No migration away from v5.0.0 commands is required.
- Existing `.githooks/*` enforcement remains required.
- Existing session adapters remain required:
  - `scripts/session/runAskCorePreCommitAdapter.mjs`
  - `scripts/session/runAskCorePrePushAdapter.mjs`
- v5.0.1 strengthens governance behavior but does not change the ASK Forge brand or the v5 runtime model.

## Recommended Upgrade Steps

1. Pull the branch or tag containing `v5.0.1`.
2. Run `npm test`.
3. Run `node ask-core/bin/ask.js preflight`.
4. Run `node ask-core/bin/ask.js can-commit`.
5. Confirm hooks are installed with `git config --get core.hooksPath`.
6. Continue closing implementation work with `ask slice close <taskId>` so each governed slice receives its own auditable commit.
