# ASK Forge v6.0.0 Release Notes

## From v5.0 and v5.1 to v6.0.0

v5.0 made ASK Forge an execution control plane: plans could be ingested into governed slices, `ask slice close` enforced OHDER validation before completion, and commits/pushes carried ASK lineage evidence.

v5.1 made OHDER smarter: semantic facts, governance validation, finding resolution, ranked refactor targets, patch-readiness checks, and council-lite architecture review moved ASK from generic architecture pressure toward explainable semantic governance.

v6.0.0 starts the language-agnostic foundation. The main shift is that ASK Forge now has compiled TypeScript contracts for the runtime shapes it already produces and the adapter/profile boundaries it needs before it can become portable across language ecosystems.

## ASK Forge Advantage in v6

ASK Forge is the governance constitution for autonomous development. Codex can implement and Superpowers can structure workflow, but ASK Forge decides how plans become governed slices, what evidence must exist before commit and push, how OHDER architecture governance participates in close, and how runtime history remains replayable.

That means v6 is not just a TypeScript cleanup. It is the release that starts turning ASK Forge from a Node-centered runtime into a portable governed software-delivery platform.

## What Changed

- Added TypeScript tooling and compile checks without rewriting the JavaScript runtime.
- Added contracts for current runtime artifacts: task board entries, plan batches, event records, runtime snapshots, and projection-facing state.
- Added typed event contracts for high-value ASK and OHDER runtime events.
- Added typed check and governance contracts for pre-commit, commit-msg, pre-push, OHDER architecture status, semantic facts, findings, and OFRR resolution records.
- Added the language adapter contract for install, format, lint, typecheck, test, build, detection, changed-file test mapping, and architecture inspection.
- Added project profile and law-pack contracts so future language/framework governance can be described before enforcement behavior changes.
- Added worker and queue contracts while preserving the current queue classes: planner, implementer, verifier, debugger, integrator, reviewer.
- Added portable JSON contract fixtures for runtime artifact families.

## Completed Boundary Waves

- Governance/OFRR: governance decisions and finding-resolution records now have explicit typed boundaries.
- EventLedger: event record shapes are represented through TypeScript contracts and fixture samples.
- RuntimeSnapshotStore: snapshot state has a typed seam for projection hydration and future replay portability.
- TaskRuntime: task lifecycle records are named contract objects instead of implicit runtime shapes.
- TaskBoardProjector: task-board projections align with the artifact contract family.
- PlanBatchRegistry: plan ingestion, slice extraction, and batch traceability have typed plan contracts.
- SliceCloseRuntime: governed close evidence now has a contract boundary while the source-compatible JavaScript runtime remains active.

## Adapter Boundary

Node/JavaScript remains first. The v6.0.0 contracts prepare ASK Forge for language-agnostic governance, but Python, PHP, .NET, Java, C++, Go, Rust, and other non-Node adapters are not implemented in this release.

## Compatibility

Source-compatible JavaScript runtime remains active. Existing CLI commands, git hook adapters, and governed slice-close workflows continue to run through the current `ask-core` implementation while TypeScript contracts define the next portability layer.

## Why It Matters

ASK Forge is moving from a Node-centered governance runtime toward a portable governed development platform. v6.0.0 does not complete that platform shift. It puts the house in order: stable contracts first, adapter implementations later.
